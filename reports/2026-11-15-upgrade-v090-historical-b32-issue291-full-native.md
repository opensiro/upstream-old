## New actual user tasks and native alternatives

**Original request:** [yottadynamics/yottacode #291](https://github.com/yottadynamics/yottacode/issues/291) identifies two missing operator tasks: revise an existing Issue after learning a correction and post a new top-level Issue comment, directly through the yottacode model's typed GitHub tools, when the shell `gh` CLI is absent or authenticated differently.

**Pinned current unmodified original:** `yottadynamics/yottacode@3f388ee03db7fbf0ec44c368a59bfd32822d1730`, MIT, original [`CONTRIBUTING.md`](https://github.com/yottadynamics/yottacode/blob/3f388ee03db7fbf0ec44c368a59bfd32822d1730/CONTRIBUTING.md). Independently re-read GitHub `refs/heads/main`: still identical on the final source-native runner. Current typed adapter has `CreateIssue`, `ReadIssue`, `AddPRComment`, but no issue-specific update/comment mutation. Supported alternatives require terminal GitHub CLI or external browser; adding a tool solely from a missing method would **not** prove need, so the first-party actor/task request in #291 is decisive.

**New operator action 1, `issue_add_comment(number,body)`:** approved GitHub Issue comment without another shell authentication context; validates input, GETs Issue to reject PR-shaped targets, then POSTs comment via typed GitHub API, returns URL/id. Empty/invalid request causes no GitHub call. On successful comment, cached Issue detail is invalidated.

**New operator action 2, `issue_update(number,title?,body?)`:** approved correction to an existing Issue. An omitted field is left **truly absent on the PATCH JSON wire**, not replaced by an empty string or default; invalid/blank title and accidental empty body fail before any mutation. GET-before-PATCH rejects PR-shaped targets. Successful mutation invalidates cached Issue detail **and** issue lists. Returns updated Issue URL and number or discriminated validation/not-found/unavailable/provider error.

**Both:** use the existing explicit per-tool `RequiresApproval` plus the source-native `Github(add_issue_comment)` and `Github(update_issue)` rule names so `deny` overrides wildcard `Github(*)` allow. An operator's actual future approval is not inferred from a native fixture, and no permission/CLA/S5 privilege has been expanded.
