# v0.10.0 — Explicit owner consent for third-party public communication

**Coverage:** prospective Upstream contribution protocol, 2026-11-15.
**Historical checkpoint:** `2aa807b8de4c81efe9169bf51db73f349f56883a`
**Checkpoint interpretation:** last observed v0.9.0 `main` before this change, **not** the future v0.10.0 release SHA.
**Source context:** [Upstream PR #303 research](https://github.com/opensiro/upstream/pull/303), [Akmatori #48](https://github.com/akmatori/akmatori/issues/48) and subsequent explicit in-chat owner instruction; **approval was not obtained before that historic public comment**.
**Protocol implementation PR:** [Upstream #315](https://github.com/opensiro/upstream/pull/315).
**SemVer:** `0.9.0 → 0.10.0` **MINOR**: newly requires human sign-off before external publicity, narrowing prior standing external PR mandate.

## Protocol changes

1. **Fail-closed public outbound consent:** before a comment, issue, review, public fork-local PR or original-project PR, show the **exact destination, action and final message/PR diff**; obtain current in-chat owner approval specific to that one write. [Normative gate](../docs/EXTERNAL_PUBLIC_COMMUNICATION_GATE.md).
2. **Standing grant narrowed:** `standing-external-publication-p1.json` retains its historical ID and issuer but removes `STANDING_NO_PER_PR_PROMPT` in favor of `EXPLICIT_OWNER_CONFIRMATION_PER_PUBLIC_ACTION`; default `BLOCK_UNTIL_EXPLICIT_OWNER_APPROVAL` for public outreach.
3. **No inference of consent:** `continue`, batched requests, source-owned need, maintainer-design uncertainty, old generic mandates, GitHub login and green tests do not constitute external-post approval. No silent comments to maintainers.
4. **No unnecessary interruption for safe research:** continue local read-only research, native tests, working branches and internal OpenSiro PRs under their own permission gates. External publication requires the separately confirmed one-time user instruction.

## Boundary and compatibility

- Prospective only. The prior authorized public PRs and unauthorized Akmatori #48 comment remain historical facts; **do not delete, fabricate approval, or rewrite old receipts**.
- Change does **not** retract ordinary preparation authority or confer third-party merge, CLA/DCO signature, account permission, VSM grade or host/runtime enforcement.
- The in-chat owner instruction is a current owner decision but not an independently verified public GitHub signature. If current conversation approval cannot be verified, **do not perform external outreach**.
- This is a **MINOR** bump under the experimental 0.x contract because an independent required publication stage changes; not an editorial patch.
