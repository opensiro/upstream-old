## Protocol changes

1. [Check the working-fork route](../docs/CONTINUOUS_WORKING_FORK_PIPELINE.md#check-the-working-fork-route-early) once a candidate is selected for implementation, before expanding a local experiment into target product code. Record the intended destination and the verified route or blocker against the existing case.
2. Use a disposable, pinned checkout for a bounded decisive experiment. For admitted work with a working-fork route, prepare the exact initial packet required by the existing executor, then use the verified contributor branch for implementation revisions, native tests, and the fork-local PR.
3. Keep source pins, reproducibility receipts, disposition and fork references in Upstream. For a blocked candidate, record the owner and next action and pause implementation until the route is resolved.

## Boundary and compatibility

Existing four-gate native fit, target policy and licensing requirements, trusted executor checks, and [separate exact-action approval before public communications](../docs/EXTERNAL_PUBLIC_COMMUNICATION_GATE.md) still apply. The early check is read-only. Existing evidence packets and frozen batches retain their historical meaning. The current registry and status schema support the handoff without migration. Tag the version at the reviewed integration commit.
